# Аналитика: платформа для обучения преподавателей СПО созданию AI-агентов

Дата: 2026-06-13. Подготовлено на основе анкет преподавателей (`Практика_агенты/Агенты_разбор/`,
26 уникальных агентов), текущих практик курса (`Docs/Доки/Практика 3.1–3.3`,
`web/instrumenty_mcp_skills_konspekt.md`) и обзора рынка платформ для создания AI-агентов
по состоянию на середину 2026 года.

---

## 1. Постановка задачи и ключевое противоречие

**Целевая аудитория курса:** преподаватели и методисты СПО Республики Татарстан.
**Ограничение:** без навыков программирования, без навыков деплоя (сервер, Docker, консоль,
переменные окружения, API-ключи в коде).
**Цель:** преподаватель самостоятельно собирает агента под свою задачу — системный промпт +
база знаний (RAG) +, в перспективе, простые инструменты — и пользуется им сам или раздаёт
коллегам/студентам ссылкой.

**Противоречие, которое нужно разрешить.** Существующий разбор 26 агентов
(`Практика_агенты/Агенты_разбор/README.md`) почти везде рекомендует **opencode** — терминальный
агент с файловыми инструментами, MCP, запуском Python-скриптов. Это отличный инструмент для
кружка по ИИ (школьники/студенты, которые учатся программировать), но **категорически не
подходит** заявленной аудитории — преподавателям без кода. Поэтому в этой аналитике критерии
жёстче, и часть из 26 агентов сознательно делится на «можно собрать no-code сегодня» и
«требует IT-поддержки/программирования — отдельный трек».

**Уже есть отправная точка.** Модуль 3 курса («Разработка ИИ-агентов с использованием
конструкторов», компетенция ПК.2.1 — «разработка и настройка ИИ-агентов на no-code
платформах») **уже построен на Yandex AI Studio**: Практика 3.1 (агент-навигатор, системный
промпт), Практика 3.2 (агент-проверяльщик, мета-промптинг), Практика 3.3 (агент с базой знаний,
File Search/RAG). Эта аналитика проверяет, насколько обоснован этот выбор на фоне альтернатив, и
даёт ответ — менять платформу или усиливать уже выбранную.

---

## 2. Критерии оценки

Для каждой платформы оцениваются:

1. **Доступ из РФ без VPN и без иностранной карты** — регистрация, оплата (рубли/безнал для
   колледжа), стабильность доступа.
2. **No-code конструктор агента** — кастомный системный промпт/инструкция через интерфейс,
   без редактирования кода.
3. **Встроенный RAG / база знаний** — загрузка документов (PDF/DOCX), поиск по ним, без
   настройки векторной БД руками.
4. **Русский язык** — качество понимания и генерации, локализация интерфейса.
5. **Цена / бесплатный лимит** — реалистичность бесплатного использования группой
   преподавателей колледжа.
6. **Порог входа для непрограммиста** — сколько концепций нужно объяснить, прежде чем человек
   соберёт первого агента.
7. **Деплой** — нужен ли сервер/Docker/хостинг, чтобы агентом мог воспользоваться кто-то
   кроме автора.
8. **152-ФЗ** — пригодность для работы с персональными данными студентов (локализация данных
   в РФ, возможность работать с обезличенными данными).

## 3. Карта инструментов по тирам

| Тир | Платформы | Суть |
|---|---|---|
| **A — основной выбор** | **Yandex AI Studio (Мастерская агентов / Agent Atelier)** | Единственная платформа, закрывающая все 8 критериев одновременно для РФ-аудитории без кода |
| **B — нишевые дополнения** | GigaChat (Sber), Aimylogic/Just AI, Salebot, Botmother, BotHub | Закрывают частные сценарии (мессенджер-боты для студентов, бесплатные токены, доступ к зарубежным моделям за рубли) |
| **C — продвинутый трек (нужен IT/деплой)** | n8n, Open WebUI, Dify, Flowise | Мощнее, но требуют сервера/Docker — для агентов с реальной файловой/Excel-автоматизацией; роль преподавателя — «оператор», а не «архитектор» |
| **D — технически сильные, но непригодны как основной инструмент в РФ** | OpenAI Custom GPTs, Google AI Studio / Gemini Gems / NotebookLM, Coze | Лучший UX в мире, но оплата/доступ из РФ нестабильны — нельзя строить институциональную программу на платформе, которая может перестать работать без предупреждения |
| **Трек 2 — факультативный «кит» (Skills + MCP)** | opencode / Claude Code (Desktop) | Терминальный AI-агент как «рантайм»: IT-специалист один раз готовит кит (MCP-серверы для файлов/Excel/sqlite + черновики SKILL.md + шаблоны), преподаватель правит готовые SKILL.md текстом и формулирует команды на естественном языке. Закрывает узкий набор «файловых/расчётных» агентов, где Yandex AI Studio принципиально не справляется (см. раздел 9) |

Дальше — подробный разбор и SWOT по каждой платформе/группе.

## 4. Тир A — Yandex AI Studio (Мастерская агентов)

### Описание

Облачная платформа Yandex Cloud для работы с LLM. Содержит:

- **Model Gallery** — YandexGPT (Pro/Lite), а также открытые модели (Llama, Qwen, GPT-OSS,
  DeepSeek и др.) под единым API и интерфейсом;
- **Мастерская агентов (Agent Atelier)** — no-code конструктор: системный промпт, выбор
  модели, температура, подключение инструментов (File Search, веб-поиск, вызов функций);
- **File Search** — встроенный RAG: загрузка PDF/DOCX/TXT, автоматическая нарезка на чанки и
  векторный поиск, без настройки векторной БД руками;
- Тестовый чат прямо в браузере — можно сразу проверить агента, без публикации.

**Доступ и оплата.** Регистрация через Yandex ID, оплата российской картой, цены указаны в
рублях с НДС (подтверждено по официальной странице тарифов). Новым аккаунтам — стартовый грант
(в материалах курса указано ~4000 ₽, что покрывает десятки занятий с группой). Привязка карты
требует подтверждающего платежа ~11 ₽ (стандартная процедура верификации, сразу возвращается).

**Стоимость в работе.** Текстовые агенты тарифицируются как: токены по тарифам выбранной модели
Model Gallery + стоимость вызовов инструментов (File Search — по данным официального прайса,
порядка 300 ₽ за 1000 запросов с НДС). При обучении группы преподавателей на бесплатном гранте
это означает сотни тестовых запусков агентов без дополнительных трат.

**152-ФЗ.** Yandex Cloud оперирует датацентрами на территории РФ — формально это российский
контур данных, что выгодно отличает платформу от иностранных сервисов. **Но** это не освобождает
от обязанности: для агентов, работающих с персональными данными студентов (характеристики,
ведомости, личные карточки), курс всё равно должен учить **обезличиванию данных перед загрузкой**
— это уже заложено в `web/instrumenty_mcp_skills_konspekt.md` как принцип «начинать с режима
только чтение» и «не передавать персональные данные студентов».

### SWOT в контексте преподавателя-непрограммиста

**Strengths (сильные стороны)**
- Полностью no-code: системный промпт собирается в форме, без единой строки кода.
- File Search закрывает 80% запросов преподавателей («справочник по…», «методист по
  нормативке», «отвечай только по загруженным документам») — это именно то, что нужно для
  RAG-агентов (01, 02, 03, 06, 07-черновик, 09, 11, 12, 15, 22, 23, 24, 25 из списка анкет).
  
- Запуск и оплата без барьеров: российская карта, рубли, грант на старте.
- Готовый учебный путь уже существует (Практики 3.1–3.3) — не нужно перестраивать программу
  с нуля, нужно усилить и расширить её.
- Тестовый чат встроен — преподаватель сразу видит результат, не нужен отдельный «фронтенд».
- Доступ к нескольким моделям (включая открытые) в одном интерфейсе — удобно для занятия
  «сравни модели на своей задаче».

**Weaknesses (слабые стороны)**
- Нет файлового вывода «в макет колледжа» (готовый docx по фирменному шаблону) — агент
  выдаёт текст в чате, оформление преподаватель переносит вручную. Для агентов 07 (РП/УМК),
  13 (расписание), 14 (ведомости), 17 (документооборот) это снижает автоматизацию до уровня
  «черновик + ручное оформление».
- Нет «настоящих» автоматизаций по расписанию (cron) и работы с Excel/базами данных —
  агенты 14, 17, 21 в полном виде здесь не реализуемы.
- Привязка к экосистеме Yandex Cloud: интерфейс рассчитан на «облачную консоль», для
  человека, далёкого от IT-терминологии (проекты, сервисные аккаунты, квоты), первые 15–20
  минут регистрации требуют сопровождения — это уже учтено в Практике 3.1 (отдельный блок
  20 минут на регистрацию).
- Зависимость от одного поставщика: если у Yandex Cloud меняются тарифы/грант-политика,
  это влияет на весь курс.

**Opportunities (возможности)**
- Постепенное добавление инструментов агенту (веб-поиск, вызов функций) даёт естественный
  «путь роста» от Практики 3.1 (системный промпт) → 3.2 (мета-промптинг) → 3.3 (RAG) →
  будущая 3.4 (инструменты/функции) без смены платформы.
- Готовые агенты можно опубликовать как виджет/API-ключ и встроить в Telegram-бота через
  n8n или в простую веб-страницу — мостик к продвинутому треку без необходимости с него
  начинать.
- Растущий грант-бюджет позволяет провести «фестиваль агентов»: каждый преподаватель
  публично тестирует агента коллеги (как уже сделано в Практике 3.1 — «перекрёстное
  тестирование»).

**Threats (риски)**
- Регуляторные изменения в РФ по «трансграничным ИИ-технологиям» в теории могут затронуть и
  отечественные облачные сервисы — но Yandex Cloud как российский провайдер находится в
  существенно более устойчивом положении, чем зарубежные альтернативы.
- Соблазн загрузить в File Search реальные ведомости/характеристики студентов «для удобства»
  — это главный методический риск занятия, который нужно явно проговаривать (обезличивание,
  тестовые данные на занятии).
- Изменение тарифов на File Search/токены после исчерпания грантов колледжа — для регулярного
  использования (не только обучения) нужно заранее оценить ежемесячный бюджет на группу
  преподавателей.

### Вывод по Тиру A

Yandex AI Studio — **обоснованный и на сегодня единственный реалистичный выбор основной
платформы**. Решение, заложенное в Модуле 3, подтверждается анализом рынка. Задача — не менять
платформу, а **дополнить программу занятием по инструментам/функциям** (следующий шаг после
File Search) и явно обозначить границу: «что собираем здесь сами, а что требует IT-поддержки».

## 5. Тир B — нишевые дополнения

### 5.1 GigaChat (Сбер)

**Что это.** Российская LLM-экосистема Сбера. Для физлиц — бесплатный лимит токенов в год
(по данным официальной документации: суммарно ~1 млн токенов/год, из них основная часть —
на младшую модель GigaChat Lite, меньшие квоты — на Pro и Max), платные пакеты в рублях.
Есть веб-чат (аналог ChatGPT) и API/SDK (GigaChain) для разработчиков.

**SWOT (для преподавателя-непрограммиста)**

| | |
|---|---|
| **S** | Бесплатный годовой лимит токенов; рублёвая оплата; декларируется как «знает российскую терминологию и нормативку» лучше иностранных моделей — хорошо для агентов 03, 07. |
| **W** | No-code конструктор агента с RAG на уровне Yandex AI Studio публично не представлен так же явно — акцент платформы на API/SDK для разработчиков (GigaChain), что возвращает к проблеме «нужен код». |
| **O** | Может использоваться как **альтернативная модель внутри связки** (если в будущем появится no-code конструктор уровня Agent Atelier) или как «второе мнение» при сравнении моделей на занятии. |
| **T** | Если преподаватель попытается повторить путь Yandex AI Studio в GigaChat самостоятельно и наткнётся на необходимость кода — это подрывает доверие к самой идее «agentless для непрограммиста». |

**Вывод:** не как основная платформа курса, но достоин **одного демонстрационного слайда** —
«вот ещё один российский провайдер моделей, бесплатный лимит, на будущее».

### 5.2 Российские low-code конструкторы ботов: Aimylogic (Just AI), Salebot, Botmother, BotHub

**Что это.** Платформы для сборки чат-ботов для Telegram/VK/сайта без кода, изначально
заточенные под продажи/поддержку, сейчас с интеграцией LLM (ChatGPT/GigaChat/YandexGPT как
«генеративный блок») и базами знаний (у Just AI — модуль RAG «Jay Knowledge Hub»). Российские
юрлица, оплата по счёту, ИП/ООО, ЭДО — удобно для закупки колледжем.

**SWOT**

| | |
|---|---|
| **S** | Готовый канал распространения — студент просто пишет боту в Telegram, без обучения работе с «облачными консолями». Подходит для агентов, ориентированных на студентов: 03 (справочник по электромонтажу), 04 (студенческий FAQ-контур куратора), 12 (карьерный навигатор). |
| **W** | Интерфейс заточен на **сценарии диалога** (интенты, ветки, скрипты) — для преподавателя, который хочет «просто системный промпт + файлы», это избыточная сложность и другой образ мышления (конструктор воронок, а не агент-консультант). |
| **O** | Естественный «второй шаг» после Yandex AI Studio: агент спроектирован и проверен там, а здесь — просто упаковывается в Telegram-бота для студентов. Можно вынести в отдельное занятие «публикация агента для студентов». |
| **T** | Если ввести этот инструмент параллельно с Yandex AI Studio на старте курса, у преподавателей возникнет путаница «зачем два конструктора» — нужно чётко разнести роли (Yandex = личный агент преподавателя, бот-конструктор = публикация для студентов). |

**Вывод:** хороший материал для **отдельного факультативного занятия «как выдать готового
агента студентам»**, но не для основной линии курса.

## 6. Тир C — продвинутый трек (требует IT/деплоя)

Эти инструменты закрывают именно те агенты из анкет, которые **не сводятся к «системный промпт
+ файлы»**: учёт успеваемости (14), расписание (13), документооборот (17), генерация docx по
шаблону колледжа (07 в полном виде), логистика (21).

### 6.1 n8n

**SWOT**

| | |
|---|---|
| **S** | Визуальный конструктор автоматизаций («форма → таблица → отчёт → уведомление») — наглядно даже без программирования, узлы соединяются стрелками. Хорошо ложится на агента 14 (ежемесячная сводная ведомость по расписанию) и 04 (FAQ-бот по orgвопросам). |
| **W** | n8n Cloud — оплата через зарубежный биллинг (иностранная карта), self-host — Docker/сервер. Само «соединение узлов» — это уже низкоуровневое программирование (переменные, выражения, JSON) — для преподавателя без подготовки высокий порог. |
| **O** | Роль преподавателя — **не строитель, а оператор**: IT-специалист колледжа один раз собирает шаблон workflow («сводная ведомость по группе»), преподаватель только заполняет форму/присылает файл. Это рабочая модель для большинства колледжей СПО. |
| **T** | Без выделенного IT-ресурса в колледже этот трек не запустится — риск, что «продвинутые» агенты останутся демонстрацией на слайде, а не практикой. |

### 6.2 Open WebUI

**SWOT**

| | |
|---|---|
| **S** | После разворачивания (один раз, силами IT) — интерфейс для конечного пользователя почти как у Yandex AI Studio: можно создавать «модели»-персоны с системным промптом и коллекцией документов (RAG) через веб-форму. Хорошо подходит для агентов с персональными данными (04, 14) — может работать с **локальной моделью (Ollama)**, данные не уходят во внешний API. |
| **W** | Деплой — Docker/сервер, часто с GPU для локальных моделей; без IT-отдела колледжа недостижимо. Локальные модели (Qwen3-8B и т.п.) слабее облачных по сложным задачам. |
| **O** | Идеальное решение именно для агентов, упомянутых в анкетах с пометкой «персональные данные → только локально» (04, 05, 12, 14, 15, 17, 24 в исходном разборе). Один сервер на весь колледж — экономично. |
| **T** | Поддержка железа/обновлений — постоянная нагрузка на IT; без неё система деградирует и доверие преподавателей к «локальному ИИ» падает. |

### 6.3 Dify и Flowise

**SWOT (объединённо — схожий профиль)**

| | |
|---|---|
| **S** | Мощные визуальные конструкторы агентных пайплайнов с RAG «из коробки»; Dify — production-grade, Flowise — на базе LangChain-узлов. |
| **W** | Облачные версии — иностранный биллинг (Stripe, нужна не-российская карта); self-host — Docker Compose, минимум 2 ядра/4 ГБ — требует сервера. Визуальные узлы оперируют понятиями «промпт-узел», «переменная», «цепочка» — это низкоуровневое программирование графами, а не «опишите задачу словами». |
| **O** | Подходят как **внутренний инструмент IT-кружка/энтузиастов** при колледже для построения сложных пайплайнов (например, каскад 07: ФГОС → РП → КТП → ФОС с промежуточными проверками) — но это отдельная аудитория, не преподаватели-непрограммисты. |

## 9. Трек 2 (факультативный): opencode/Claude Code как «расширенный готовый агент» через Skills + MCP

### 9.1 Откуда взялся этот раздел и честная переформулировка

После основного анализа возникла гипотеза: opencode/Claude Code можно дать преподавателю не
как «среду программирования», а как **рантайм агента**, которым преподаватель управляет
исключительно через (а) правку файлов `SKILL.md` — методичек на естественном языке — и
(б) команды в чате, а доступ к файлам/Excel/БД даёт заранее подключённый **MCP**. Эта гипотеза
была проверена отдельным исследованием (12 субагентов: оценка окружения, Skills, MCP, цены
backend-моделей и пересмотр 6 «сложных» агентов — 07-полный, 13, 14, 17, 20, 21).

**Вывод исследования — да, но не в том виде, как сформулирована гипотеза.** SKILL.md
действительно можно писать обычным текстом, и инструмент **skill-creator** (мета-скилл от
Anthropic) даёт диалоговый режим написания скилла — прямой аналог Практики 3.2
(мета-промптинг). Но качественный SKILL.md с точными триггерами `description`, обработкой
ситуаций «файл не найден / формат другой» и проверкой на нескольких входных файлах — это
**спецификация программы на естественном языке**, требующая навыков декомпозиции задачи. У
целевой аудитории курса таких навыков по определению нет, и при поломке окружения преподаватель
не сможет диагностировать причину (для него это выглядит как «агент просто не отвечает»).

Поэтому честная формулировка роли Track 2: **это не «преподаватель строит агента сам», а
«расширенный готовый агент с предзаготовленным китом от IT-специалиста», который преподаватель
донастраивает текстом и эксплуатирует**. При таком позиционировании трек оправдан для
**3-5 из 26 идей анкет (~15-20%)** — там, где задача принципиально требует работы с локальными
файлами (Excel/docx/sqlite), детерминированных вычислений (формулы, а не LLM-арифметика) и/или
локальной обработки персональных данных по 152-ФЗ. Для остальных ~80-85% идей Yandex AI Studio
остаётся более надёжным и дешёвым в поддержке вариантом.

### 9.1-бис. Жёсткая граница: подключение MCP — это работа IT, а не действие преподавателя

Чтобы не было двусмысленности: **«подключить MCP» — это НЕ no-code задача.** Подключение
MCP-сервера означает правку конфигурационных файлов (`.mcp.json` / `opencode.json`), запуск
команд `npx`, установку Node.js/Pandoc, прописывание API-токенов, иногда OAuth-авторизацию
(Google Drive, Telegram). Это деплой и околопрограммирование — ровно тот класс задач, который
по условию курса целевая аудитория не выполняет. **Преподаватель MCP не подключает. Точка.**
Это всегда делает IT-специалист один раз при сборке кита.

Отсюда прямой ответ на закономерный вопрос «что проще освоить»:

> **Если преподаватель делает всё сам — собрать агента с нуля в Yandex AI Studio безусловно
> проще, чем взять opencode/Claude Code, написать скиллы и подключить MCP.** В Студии «с нуля»
> — это браузер, текст системного промпта и загрузка файлов кнопкой; ломаться на компьютере
> преподавателя нечему. В opencode «сам» — это установка приложения, правка JSON-конфигов MCP,
> токены и диагностика локальных сбоев, то есть как раз программирование/деплой. Сравнивать их
> как равные «два способа собрать агента самому» — некорректно: opencode «сам» для непрограммиста
> нереалистичен в принципе.

Из четырёх составляющих агента паритет между платформами есть **только в одной** — описание
логики текстом (системный промпт ≈ SKILL.md). Остальные три (установка, подключение
данных/инструментов, диагностика сбоев) в opencode либо сложнее, либо невыполнимы для
непрограммиста:

| Составляющая | Yandex AI Studio (преподаватель сам) | opencode/Claude Code |
|---|---|---|
| Установка/запуск | ничего, браузер | приложение + Node + Git (IT) |
| Подключение данных/инструментов | загрузка файлов кнопкой | **правка конфигов MCP, токены, OAuth (IT)** |
| Логика агента | системный промпт текстом | SKILL.md текстом — **паритет** |
| Если сломалось | ломаться нечему | локальная диагностика (преподаватель не сможет) |

**Вывод, который должен быть проговорён явно:** opencode/Claude Code оправдан не потому, что
его «легче освоить» (он сложнее), а исключительно потому, что он закрывает 3-5 файловых/
расчётных агентов, недоступных Yandex AI Studio — и закрывает их **руками IT, который готовит
кит**, а не руками преподавателя. Для преподавателя его доля в Track 2 сводится к правке
готового текста SKILL.md и командам на естественном языке. Никакой самостоятельной «сборки
агента в opencode» от преподавателя курс не требует и требовать не может.

### 9.2 Критические риски — почему это не альтернатива Yandex AI Studio, а узкая надстройка

1. **Оплата/доступ из РФ — главный блокер.** Claude (Claude Code/Claude Desktop) официально
   недоступен для оплаты рублёвой картой; реалистичный путь — серые финтех-посредники
   (агрегаторы типа ClaudeStore, наценка 15-25%) или прокси-сервисы для backend-моделей
   (например ProxyAPI.ru с DeepSeek). Для гособразовательного учреждения зависимость
   «второго трека» от теневой платёжной инфраструктуры с первого шага — репутационный и
   юридический риск, который должен явно обсуждаться с организаторами курса до внедрения.
2. **Хрупкость окружения на корпоративных машинах колледжей.** Антивирусы блокируют
   npx/node-процессы, нет прав администратора на установку Node.js/Git/Pandoc, групповые
   политики блокируют консоль. Любое обновление Claude Code/opencode или npm-пакета MCP может
   сломать связку без понятной ошибки — для преподавателя это «агент ничего не делает». Кит
   превращается в статью постоянных расходов на сопровождение IT, а не разовую настройку.
3. **Грань «без кода» размыта, а подключение MCP за неё прямо выходит.** См. раздел 9.1-бис:
   подключение MCP — это правка конфигов/токенов/OAuth, то есть деплой, который преподаватель
   не делает. Даже оставшаяся ему часть — хороший SKILL.md с точными триггерами — требует
   мышления, близкого к декомпозиции программы, просто без синтаксиса.
4. **Малая дифференциация для большинства кейсов.** Если IT готовит весь кит, а преподаватель
   только формулирует команды и правит текст — разница с «хорошо написанным системным
   промптом в Agent Atelier» минимальна для нефайловых задач. Реальное преимущество (локальные
   файлы, детерминированные расчёты, локальные ПДн) — только в узком подмножестве.
5. **152-ФЗ для агентов 14/17.** Локальный запуск (Ollama + filesystem/sqlite MCP, без
   облачного API) снижает риски трансграничной передачи, но требует ПК с GPU 12 ГБ+ в колледже
   и организационных мер (шифрование диска, журналирование доступа MCP, разграничение прав) —
   это ответственность колледжа как оператора, а не настройка инструмента.
6. **«Чёрный ящик» сгенерированного кода.** Если агент генерирует HTML/JS (агент 20) или
   Python-скрипты, преподаватель не может аудировать их на корректность/безопасность — риск
   ошибок в демонстрации или, через filesystem MCP, риск порчи/утечки файлов.

### 9.3 Состав «кита», который IT-специалист готовит один раз

- **Рантайм:** Claude Desktop (вкладка Code) как основной вариант — при решённом вопросе
  оплаты (рублёвый агрегатор/прокси с DeepSeek-backend, либо Yandex AI Studio API как
  OpenAI-совместимый backend). opencode — резервный вариант без зависимости от
  Anthropic-аккаунта. На Windows дополнительно ставится Git for Windows.
- **MCP-серверы**, прописанные в `.mcp.json`/`opencode.json` (преподаватель не редактирует
  JSON):
  - `filesystem` (доступ только к рабочей папке колледжа) — почти всегда;
  - `@negokaz/excel-mcp-server` (npx, Node 20+) — для агентов 14, 21;
  - `mcp-server-sqlite-npx` — для агента 17;
  - `mcp-pandoc` + системно установленный Pandoc — для агента 07 (генерация .docx по шаблону);
  - опционально: веб-поиск (Brave/Tavily MCP), Telegram-MCP (разовая авторизация через
    my.telegram.org), Google Drive MCP (OAuth через Google Cloud Console) — точечно под кейс.
- **Готовые шаблоны и заготовки:** фирменный Word reference-doc колледжа для Pandoc (07);
  эталонные образцы РП/КТП/ФОС в `references/` (07); пустая sqlite-БД `tracker.db` с готовой
  схемой (17); заготовка Excel с формулами маршрутов/тарифов (21); внешний планировщик
  (cron/Task Scheduler) для регулярных проверок (17) — это не входит в логику Skills и
  настраивается IT отдельно.
- **Черновики `SKILL.md`** под каждый из целевых кейсов — преподаватель получает не пустой
  лист, а готовый текст, который правит и адаптирует с помощью `skill-creator`.

### 9.4 Как с этим работает преподаватель (после получения кита)

1. Открывает приложение (Claude Desktop, вкладка Code) в папке кита — видит чат, не терминал.
2. Читает готовый `SKILL.md` как методичку (триггер → шаги → формат результата → ограничения)
   и правит формулировки текстом: пороги («должник — это >3 пропусков» → «>5»), формулы,
   названия полей, формат итогового документа, новые правила.
3. Для нового скилла — описывает задачу обычными словами; встроенный `skill-creator` задаёт
   уточняющие вопросы и пишет черновик, преподаватель читает и редактирует текст.
4. Кладёт исходные файлы (Excel-журналы, РП, списки) в рабочую папку — перетаскиванием.
5. Даёт команду на естественном языке: «Посчитай успеваемость группы за семестр и сохрани
   сводную ведомость», «Сделай РП по дисциплине Х на основе файлов в папке».
6. Проверяет результат по контрольным примерам («при весе 1000 кг итог должен быть Х₽»); если
   неверно — словесно описывает проблему и просит исправить логику.
7. При поломке окружения (агент не отвечает, MCP не подключился) — обращается к IT, а не
   диагностирует сам. Это нормальный, ожидаемый сценарий, а не провал курса.

### 9.5 Пересмотренные вердикты по 6 «сложным» агентам

| № | Агент | Пересмотренный вердикт |
|---|---|---|
| 07-полный | Разработчик РП и УМК (каскад → docx) | Доступно частично, с китом IT — преподаватель пишет/правит каскад SKILL.md (РП → КТП → ФОС) и сам шаблон в Word; reference-doc, образцы и MCP (`filesystem`+`mcp-pandoc`) готовит IT. |

### 9.6 Как встроить в программу курса

1. Текущая структура курса на Yandex AI Studio остаётся **основной и обязательной для всех** —
   покрывает ~20-23 из 26 идей, изменений в логике подачи не требует.
2. Добавить **отдельный факультативный модуль «Продвинутый трек: агенты с доступом к файлам»**
   в конце программы (после того как все собрали прототипы в Studio) — например, занятие 9-10
   из 8-10-занятийной программы, опционально для тех, чьи идеи попадают в категорию
   «файловые/расчётные/локальные ПДн».
3. Перед этим модулем — **отдельная организационная сессия для IT-специалистов колледжей** (не
   для преподавателей): установка кита, решение вопроса оплаты/backend, подготовка
   MCP-конфигов и шаблонов под конкретные кейсы. Это технический интенсив, проводимый ДО
   модуля для преподавателей.
4. В самом модуле — формат «разбор готового кита»: преподаватель получает рабочую папку с
   агентом и (1) учится читать/редактировать `SKILL.md` как методичку, (2) тренируется
   формулировать команды, (3) разбирает 1-2 примера правки скилла через диалог со
   `skill-creator` (аналог Практики 3.2), (4) проходит контрольный сценарий «что делать, если
   агент не отвечает / результат неверный» — с явным разделением «правлю сам / зову IT».
5. В демонстрационные материалы модуля включить **07-полный, 14, 21** (и опционально 17 в
   упрощённой версии без планировщика) как наиболее реалистичные кейсы «доступно частично, с
   китом». Агент 13 — либо исключить из демо продвинутого трека, либо показать как «демо
   границ» с явным проговариванием, что итог здесь — во многом результат работы программиста.
   Агент 20 — аналогично, как «демо границ» (генерация неаудируемого кода).
6. В вводное занятие по выбору платформы добавить короткий блок (15-20 минут) — честное
   сравнение «Studio vs продвинутый трек» с проговариванием рисков из раздела 9.2, чтобы
   преподаватели осознанно выбирали, нужен ли им второй трек, и не ожидали большей
   автономности, чем он реально даёт.

## 10. Итоговая рекомендация

### 10.1 Платформа

**Оставить и усилить Yandex AI Studio (Мастерская агентов) как основную платформу курса.**
Альтернативы либо технически слабее в части no-code+RAG (GigaChat), либо требуют деплоя
(n8n/Open WebUI/Dify/Flowise), либо нестабильно доступны из РФ без VPN и иностранной карты
(OpenAI, Google, Coze). Ни одна другая платформа не закрывает одновременно «no-code + RAG +
оплата рублями без VPN + русский язык» — а это и есть жёсткий набор требований аудитории.

### 10.2 Что добавить в программу

1. **Занятие «Инструменты и функции агента»** (логичное продолжение после Практики 3.3) —
   показать, как агенту в Agent Atelier подключить веб-поиск/вызов функций. Это закрывает
   агента 26 (монитор законодательства) и усиливает 11 (подборщик ресурсов).
2. **Явный модуль про 152-ФЗ и обезличивание** — короткое занятие *до* практик с
   персональными данными (агенты 04, 05, 10, 14, 15, 24): что можно загружать в облачный
   агент, а что — нет, и как обезличить данные для тренировки. Материал для этого уже частично
   есть в `web/instrumenty_mcp_skills_konspekt.md` (раздел «Безопасный запуск»).
3. **Факультативное занятие «Публикация агента для студентов»** (Тир B — бот-конструкторы) —
   для агентов 03, 04 (FAQ-часть), 12: преподаватель переносит готовый и проверенный промпт +
   базу знаний в Telegram-бота.
4. **Факультативный модуль «Продвинутый трек» (раздел 9)** — для агентов 07-полный, 14, 21
   (и опционально 17): opencode/Claude Code + Skills + MCP как «расширенный готовый агент» с
   китом от IT. Проводится после того, как все собрали прототипы в Studio, и требует отдельной
   организационной сессии для IT-специалистов колледжей.
5. **Карта «продвинутого трека» для завучей** — отдельная страница/слайд: какие агенты (13, 14,
   17, 21, полный 07) требуют IT-специалиста и какой инструмент (n8n/Open WebUI или кит из
   раздела 9) для этого подойдёт. Цель — не разочаровать преподавателей, у которых нет таких
   ресурсов, а дать реалистичную картину «это тоже возможно, но другим способом».

### 10.3 Чего НЕ делать

- Не вводить opencode/Claude Code как альтернативную основную платформу и не обещать
  преподавателям, что они «построят агента сами» в этом инструменте — честная роль описана в
  разделе 9: это факультативный «кит» от IT для узкого круга файловых/расчётных кейсов
  (~3-5 из 26 идей), а не замена no-code конструктора.
- Не вводить Track 2 без решённого вопроса оплаты/доступа из РФ и без постоянного
  IT-сопровождения — без этого «разовая настройка» превращается в источник постоянных сбоев,
  которые подрывают доверие к курсу в целом (раздел 9.2).
- Не показывать на практике инструменты Тира D (Custom GPTs, Gemini Gems/NotebookLM, Coze) как
  «то, что вы будете строить» — только как обзорную справку, чтобы не создавать ситуацию, когда
  часть аудитории не может повторить шаги из-за недоступности сервиса.
- Не предлагать GigaChat и российские бот-конструкторы как замену Yandex AI Studio — это
  дополнения для конкретных сценариев (бесплатные токены, публикация для студентов), а не
  альтернативная основа курса.
