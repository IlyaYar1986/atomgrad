# Страница-лонгрид вебинара

## Порядок работы

1. **Прочитай контекст проекта:** `CLAUDE.md`, `SYSTEM_PROMPT.md`, `reference/PATTERNS.md`. Если делаешь первую страницу — открой `reference/etalon_lekciya.html` целиком, чтобы увидеть живой пример всех блоков.
2. **Сначала план, потом код.** Создай `Docs/<имя_страницы>_plan.md` по образцу `reference/etalon_plan_stranicy.md`: таблица секций (номер, `id`, заголовок, номер картинки), затем текстовые промпты для генерации инфографики. Согласуй план с пользователем до вёрстки.
3. **Верстай от шаблона:** скопируй `web/TEMPLATE_stranica.html` под именем страницы и заменяй контент. Не начинай HTML с нуля и не вводи новых систем стилей.
4. **Проверь в браузере по HTTP** (`python3 -m http.server 8000`), не через `file://`.
5. **Напиши структурный тест** `tests/check_<имя>_page.py` по образцу `reference/etalon_test.py` и прогони весь набор.

## Обязательные элементы страницы

- Фиксированный навбар со ссылкой «← Оглавление», названием блока и якорями секций.
- Hero: бейджи (блок · длительность · аудитория), заголовок с `<em>` на акцентном слове, подзаголовок-обещание результата, обзорная инфографика, сетка быстрых ссылок.
- 5–9 нумерованных секций со стабильными `id` (`s1`…`sN`) и градиентными бейджами по порядку.
- Чек-лист с прогрессом в localStorage (уникальный ключ на страницу) и квиз с разбором ответов.
- Заключение из пронумерованных выводов.
- Оверлеи лайтбокса и фуллскрина iframe + весь JS из шаблона.

## Правила контента

- Аудитория — руководители и сотрудники малого и среднего бизнеса. **Все примеры из бизнес-практики**: продажи, закупки, склад, найм, поддержка, документооборот, отчётность. Примеры из школ, колледжей и вузов не использовать.
- Ценность считается в часах сотрудника, стоимости ошибки и сроке окупаемости.
- Только сервисы, доступные в РФ без VPN и зарубежной карты — либо с явной пометкой об ограничении. **Каждое упоминание сервиса — с активной ссылкой.**
- Цифры — с источником; если данные от самого вендора, оговорить.
- В каждом блоке, где обещается результат, назвать границу: что остаётся за человеком, где подход не работает.
- Метафора рядом с каждым техническим термином, а не вместо него.
- Типографика: «ёлочки», тире «—», буква «ё».

## Инфографику ты не генерируешь

Пишешь текстовые промпты в план (16:9, светлый лавандово-белый фон, панели со скруглениями, pill-заголовки секций, стеклянные 3D-иконки, нижний нумерованный степпер, весь текст по-русски, без водяных знаков и реальных логотипов) — изображения генерирует человек. В HTML сразу ставь `onerror`-заглушку с описанием того, что там будет, чтобы страница выглядела целой до появления PNG. Подробности — `reference/PROMPTY_INFOGRAFIKI.md`.

## Чего не делать

- Не подключать внешние CDN, шрифты и библиотеки — всё офлайн, шрифты системные.
- Не переизобретать демо, которое уже есть в `web/` — встраивай через iframe-карточку.
- Не изобретать анонсы практик и занятий, которых нет в согласованном плане.
- Не мельчить: страницу смотрят с проектора, размеры через `clamp()`.
