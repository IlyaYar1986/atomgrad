# CLAUDE.md

Инструкции для Claude Code при работе с этим репозиторием.

## О проекте

Статический сайт вебинара «ИИ-агенты для бизнеса» на русском языке. Никакого фреймворка, пакетного менеджера, бандлера и сборки — чистый HTML5 со встроенными CSS и vanilla JS. Страницы самодостаточны: открываются напрямую или раздаются как статика.

**Аудитория — руководители и сотрудники малого и среднего бизнеса** (собственники, операционные директора, руководители отделов, менеджеры), без технического бэкграунда. Страницы показываются на проекторе во время живого вебинара и открываются участниками самостоятельно после него.

## Команды

- Локальный запуск: `python3 -m http.server 8000` из корня проекта, затем `http://127.0.0.1:8000/`. На `file://` не полагаться — страницы встраивают локальные iframe, которым нужен HTTP.
- Тесты: `python3 -m unittest discover -s tests -p "check_*.py" -v` из корня.
- Один тест: `python3 -m unittest tests.check_<имя>_page -v`.
- Линтера, форматтера и шага сборки в проекте нет.

## Структура репозитория

- `index.html` / `oglavlenie.html` — главная страница и оглавление вебинара.
- `web/` — страницы блоков вебинара и отдельные интерактивные демо (по одному HTML-файлу на демо). Крупные страницы несут собственный встроенный CSS; мелкие демо могут подключать `web/shared.css`.
- `png/` — инфографика, по подпапке на страницу (`png/<имя_страницы>/01_....png`).
- `Docs/` — планы страниц, исходные тексты, промпты для генерации инфографики.
- `reference/` — **эталоны из предыдущего проекта**: образцы вёрстки, плана, теста. Читать перед первой страницей, копировать код и структуру, но не смыслы (см. предупреждение в `README.md`).
- `source_material/` — исходный фактический материал по агентам, MCP, Skills и платформам. **Требует переработки под бизнес-аудиторию.**
- `tests/` — структурные проверки страниц на Python `unittest`.

## Архитектура и соглашения

- **Язык интерфейса — русский.** Весь контент для участников и комментарии в HTML пишутся по-русски.
- **Дизайн-система:** светлый фон slate, белые карточки, индиго как основной акцент, cyan/teal как вторичный, фиксированный горизонтальный навбар, нумерованные градиентные бейджи, мягкие тени, скруглённые карточки. Следовать визуальному языку `reference/etalon_lekciya.html`, а не вводить новую систему стилей.
- **Композиция страницы:** крупная страница — один самодостаточный HTML-файл со встроенными `<style>`/`<script>`. Мелкие демо в `web/` могут подключать `web/shared.css`.
- **Переиспользование вместо дублирования:** существующие демо встраиваются `<iframe>`-карточкой с кнопкой фуллскрина, PNG — с лайтбоксом и зумом по клику. Не переизобретать уже существующую визуализацию.
- **Адаптивная типографика:** `clamp()` для размеров шрифта, медиазапросы для сеток. Страницы смотрят с проектора — не мельчить.
- **Навигация:** у секций стабильные `id`, навбар подсвечивает активную через `IntersectionObserver`.
- **Пути:** страницы в `web/` ссылаются на картинки как `../png/...`, на соседние демо — по имени файла. В именах файлов встречается кириллица и пробелы: всегда брать точные имена через `find`/`rg --files` и цитировать пути в shell (на macOS Unicode-нормализация делает визуально одинаковые имена разными по байтам).
- Не вводить фреймворки, бандлеры и не затевать несвязанные реструктуризации — это осознанно zero-build статика.

## Правила контента

- **Все примеры — из бизнес-практики МСБ**: продажи, закупки, склад, найм, поддержка клиентов, документооборот, отчётность, маркетинг. Никаких примеров из школ, колледжей и вузов — они остались в предыдущем проекте и этой аудитории не подходят.
- **Только сервисы, доступные в РФ**, без VPN и зарубежной карты, либо с явной пометкой об ограничении.
- **Каждое упоминание сервиса — с активной ссылкой** на его сайт или документацию.
- **Цифры — с источником.** Если данные исходят от самого вендора, оговорить это.
- **Антихайп:** явно разделять «работает уже сегодня», «работает с оговорками» и «пока не работает»; называть, что остаётся за человеком.
- Практики и упражнения даются только те, что раскрыты в тексте самой лекции — не изобретать анонсы несуществующих занятий.

## Тестирование

Тесты в `tests/` — `unittest`-кейсы, разбирающие HTML через `html.parser.HTMLParser` и проверяющие структурные инварианты: обязательные `id` секций, отсутствие дублей `id`, наличие ключевых текстовых маркеров, корректность ссылок между страницами, что встроенные демо существуют и самодостаточны (без внешних CDN). Образец — `reference/etalon_test.py`. При изменении страницы, покрытой тестом, сверяться с ожидаемыми в нём id, маркерами и ссылками.

Автоматизированных браузерных тестов нет: интерактив проверять вручную в браузере по HTTP — десктопная и мобильная ширина, фиксированный навбар, аккордеоны, лайтбокс, фуллскрин-оверлей iframe, консоль без ошибок.
